## 0. 方向变更（v2.0）

### 0.1 结论

- **不做实时/双向同步**；不依赖 S3、rclone、remotely-save。
- **门户成为日记主系统**；Obsidian 只作为一次性导入来源，之后可不再使用。
- **Markdown 仍是内容格式**：门户在 Ubuntu 本地维护 `~/文档/portal-diary/`，保留日/周/月/季/年目录结构；网页直接读写这些 md。
- 现有 Obsidian 日志通过「上传 zip」一次性导入；导入后可整包导出备份。

### 0.2 存储布局

```
~/文档/portal-diary/
├── 2026/日记/2026-10-21.md
├── 2026/周记/2026-W43.md
├── 2026/月记/2026-10.md
├── 2026/季度/2026-Q3.md
├── 2026/2026年记.md
├── 2025/2025-06-16.md        # 历史扁平路径原样保留
├── 2023/...
└── Template/...
```

- 文件即主存储；SQLite 只做可选索引（路径 / 日期 / 标签 / 哈希），可整表重建，不存正文。
- 导入保留原相对路径；日期从文件名解析；无法识别的路径进入「未分类」并提示。
- 门户路径与 `E:\文档\笔记` 解耦：导入后门户自持一份，不再回写 Obsidian。

### 0.3 导入（一次性）

- 网页「上传 Obsidian 日志」：选择 `.zip`（`1.Diary/` + `Template/`，或整库后过滤），后端安全解压（防 zip-slip），写入门户存储，返回「导入 / 跳过 / 失败」清单。
- 也支持 CLI 导入；首次迁移可直接通过 SSH 把现有 vault 传上 Ubuntu。
- 幂等：同路径同内容跳过；同路径不同内容按 `overwrite` 选项处理。
- 导入后生成索引；提供「导出 zip」备份。

### 0.4 Thino / 网页功能

- 保留 `Memos` 段与 `- HH:mm 内容` 格式；网页提供快速记录、时间线、`#标签`、编辑/删除。
- 不再与 Obsidian 双写，因此**不需要 409/冲突检测**；只保留同浏览器多标签页的基础保护（可选 `base_sha256`）。

### 0.5 API / UI 概要

- `POST /api/diary/import`（zip 或 JSON 文件清单）
- `GET /api/diary/entries`、`GET /api/diary/entries/{date}`、`PUT /api/diary/entries/{date}`、`POST /api/diary/entries`
- `GET/POST/PATCH/DELETE /api/diary/memos`
- `GET /api/diary/export`
- 「日记」页签：左侧年月/日历，右侧编辑器 + 预览，顶部 memo 条，Memos 时间线，导入/导出按钮。

### 0.6 分阶段

- **P0**：门户存储 + zip 导入现有日志 + 今日/按日期只读 + memo 追加 + 导出 zip。
- **P1**：全文编辑、周/月/季/年导航、memo 编辑/删除、标签/搜索。
- **P2**：附件、反向链接、版本历史。

### 0.7 待确认

1. 存储用「门户本地 Markdown 文件」（推荐）还是 SQLite 正文？
2. 上传方式：网页 zip（推荐）还是我直接通过 SSH 拷过去？
3. 导入范围：只日记，还是周/月/季/年全量？
4. `Memos` 段保留（推荐，兼容旧格式）还是改独立表？
5. 是否允许网页删除文件？
6. 写接口是否加 `X-Diary-Token`？

## 1. 目标、非目标与用户场景

### 1.1 目标

- **Markdown 是唯一内容源**：日记正文、周/月/季/年记、Thino Memos 均以 vault 内 `.md` 文件为准；门户不将日记正文迁入 SQLite 作为主存储。
- **目录结构不变**：新建与保存遵循现有路径约定（见 §4），与 Obsidian 打开同一文件。
- **网页「日记」页签**：按日期浏览/创建、Markdown 编辑 + 预览、保存；P1 起支持周/月/季/年导航。
- **网页 Thino 式能力**：在当日日记的 `Memos` 段快速追加、时间线展示、`#标签` 解析、编辑/删除单条 memo，格式与 Obsidian Thino（`MemoSaveLocation: DAILY`）兼容。
- **Ubuntu 门户可读写**：通过 S3 与 Windows/iPhone 上的 remotely-save 桥接，不要求在 Ubuntu 安装 Obsidian。

### 1.2 非目标

- 不替代 Obsidian 作为主笔记环境；不实现完整 Thino 插件功能（置顶、任务完成态、Moments、HTTP API 等见 §11）。
- 不在 P0/P1 实现附件、Excalidraw、反向链接图谱、自动 Templater 脚本执行。
- 不把整库 34MB vault 镜像到 Ubuntu；仅同步日记相关子树。
- 不改动 remotely-save 的 S3 服务商选择（由用户现有配置决定）。

### 1.3 用户场景

| 场景 | 入口 | 期望 |
|------|------|------|
| 晚间在电脑写长文日记 | 门户「日记」页签 | 编辑 `## 杂记` 等区域，Ctrl+S 保存并推 S3 |
| 白天随手记一条想法 | 页签顶部快速 memo 条 | 追加 `- HH:mm 内容` 到当日 `Memos`，手机稍后 Obsidian 可见 |
| 手机上 Thino 记 memo | Obsidian + Thino | 写入同日 `Memos`；回电脑前门户拉取后可见 |
| 写周记/月记 | P1：粒度切换 | 打开 `周记/2026-W43.md` 等，同一编辑器 |
| 冲突 | 任一端 | 保存前检测远端变化，禁止静默覆盖，提示合并或另存 |

## 2. 现状与约束

### 2.1 门户技术栈

- Python 标准库 HTTP 服务（`app/server.py`）：`GET/POST/PATCH/DELETE` + JSON `{"ok": true/false, "error": "..."}`。
- 前端：原生 HTML/CSS/JS；页签在 `web/index.html`，模块按页懒加载（参考 `web/js/stories.js` 的 `api()` 与切页加载模式）。
- 路径常量：`app/paths.py`（`PROJECT_ROOT`、`DATA_DIR` 等）；小故事数据在 SQLite，**日记模块应读写文件系统，不沿用 stories 表存正文**。

### 2.2 Vault 结构（观测）

- 日：`1.Diary/YYYY/日记/YYYY-MM-DD.md`（2026 年起）；历史年份存在扁平命名（如 `2025/2025-11-13.md`、`2023/2023-08-17 周四.md`），实现时需「按年解析规则表」或仅保证新年份路径。
- 周：`1.Diary/YYYY/周记/YYYY-Www.md`（如 `2026-W43.md`）；模板链接占位符为 `{{date:gggg-[W]ww}}`。
- 月：`1.Diary/YYYY/月记/YYYY-MM.md`。
- 季：`1.Diary/YYYY/季度/YYYY-Qn.md`。
- 年：`1.Diary/YYYY/YYYY年记.md`。
- 模板：`Template/日记模板.md`（首行 wiki 链占位、## 杂记、空 Memos 段）。

### 2.3 单日日记结构（格式契约）

- 典型无 YAML frontmatter；首行可为周/月/年 wikilink。
- `## 杂记` 下为编号列表等自由 Markdown。
- 独立一行标题 **`Memos`**（非 `## Memos`，与现有文件一致）。
- Memos 条目：`- HH:mm ` + 内容；多行续写用**单个 Tab** 缩进后续行（Thino `DefaultTimePrefix: HH:mm`，`InsertType: end`）。

### 2.4 Thino 相关配置（来自插件 data.json，不含密钥）

- `MemoSaveLocation: DAILY` → 写入当日日记文件。
- `DefaultMemoComposition: "{TIME} {CONTENT}"` → 列表行形态 `- {TIME} {CONTENT}`。
- `saveThinoType: FILE`；`ProcessContentTarget: custom`；`InsertAfter` / `ProcessEntriesBelow` 为空 → 以文件末尾 `Memos` 段为准（与样本一致）。
- `FetchMemosMark: #memo` 未用于 DAILY 模式主路径；网页标签搜索仍解析行内 `#tag`。
- `EnabledHttpApi: false` → 门户不依赖 Thino HTTP API。

### 2.5 同步与部署约束

- Windows / iPhone：**remotely-save → S3**，用户**手动**触发同步。
- Ubuntu：**当前无笔记库、无 rclone**；门户只读本地 `data/` 与静态 `web/`。
- 日记子树体量约 **0.1MB**（103 个文件量级），整库约 34MB。
- 访问面：Tailscale / 局域网；**无登录鉴权**（与现网一致）。

## 3. 架构方案对比与推荐

### 3.1 方案概览

```
                    ┌─────────────────┐
  Obsidian ────────►│ remotely-save   │
  (Win/iPhone)      │  (手动 sync)    │
                    └────────┬────────┘
                             │ S3
                    ┌────────▼────────┐
                    │ rclone          │
                    │ (Ubuntu)        │
                    └────────┬────────┘
                             │ 本地目录
                    ┌────────▼────────┐
                    │ 门户 diary API  │
                    │ 读写 *.md       │
                    └─────────────────┘
```

### 3.2 对比表

| 维度 | A. 本地镜像 + rclone↔S3 | B. rclone 直读写的 S3 对象 | C. Ubuntu WebDAV 替代 S3 | D. Syncthing |
|------|-------------------------|----------------------------|--------------------------|--------------|
| Ubuntu 改动 | 安装 rclone、cron/systemd 定时或按需 sync；镜像目录 | 每次 API 调 rclone copyto/cat；延迟高 | 部署 WebDAV；改 remotely-save 端点 | 安装 syncthing；双端配对 |
| 门户读写 | 普通 `open()`/`write()`，简单可靠 | 子进程 rclone，需缓存 ETag | 同 A 或直读 WebDAV | 同 A |
| 冲突风险 | 中：需 pull→edit→push 协议 | 中–高：并发直写 S3 更易撞车 | 中 | 低–中（有版本机制） |
| iPhone | 不变（仍 S3） | 不变 | **需改 remotely-save 配置** | 需 Möbius Sync 等 |
| 依赖 | rclone + S3 凭据 | rclone | WebDAV 服务 + TLS | Syncthing 生态 |
| 与现网契合 | **高** | 中 | 低（动手机/PC 同步目标） | 中（新组件） |

### 3.2.1 方案 B 的补充说明

若选 B：每次 `GET` 执行 `rclone cat remote:path/file.md` 到临时文件或内存，`PUT` 先 `cat` 比对 hash 再 `rclone copyto`。优点是无常驻磁盘副本；缺点是延迟、并发与 rclone 锁；**在 0.1MB 子树场景下收益小于 A 的复杂度**。若未来镜像整库，可再评估 B + 本地 LRU 缓存。

### 3.3 推荐：**方案 A（本地镜像）**

**理由：**

1. 与「文件优先、零依赖 Python 服务」一致：日记模块与 `stories.py` 不同，直接 `pathlib` 读写镜像目录，无需每次请求起 rclone。
2. 不改变 Windows/iPhone 的 remotely-save（仍 S3），用户操作流程增加的是「用门户前/后 optionally 在 Obsidian 点同步」，协议清晰。
3. 子树 0.1MB，全量 `rclone sync` 延迟可接受；冲突检测可在**单文件**粒度用保存前 pull + 内容哈希比对。
4. 方案 B 适合极大库或磁盘极紧场景；当前数据量下 A 更简单，B 可作为 P2 优化（热文件缓存 + 冷文件按需拉取）。

**镜像范围（建议默认）：** `1.Diary/` 全树 + `Template/`；不含 Annex/其他库。是否含历史 2023–2025 异构路径见 §11。

**Ubuntu 路径（建议）：** `~/文档/笔记-mirror/` 映射 S3 上 vault 根，或 rclone `remote:bucket/path/to/vault/` → 本地；`app/diary.py` 通过配置项 `DIARY_VAULT_ROOT` 指向该目录下的 `1.Diary` 与 `Template`。

## 4. 文件模型

### 4.1 路径解析

| 粒度 | 相对路径（2026+ 规范） | 文件名示例 |
|------|------------------------|------------|
| day | `{Y}/日记/{Y}-{M}-{D}.md` | `2026/日记/2026-10-21.md` |
| week | `{Y}/周记/{Y}-W{ww}.md` | `2026/周记/2026-W43.md` |
| month | `{Y}/月记/{Y}-{MM}.md` | `2026/月记/2026-10.md` |
| quarter | `{Y}/季度/{Y}-Q{n}.md` | `2026/季度/2026-Q3.md` |
| year | `{Y}/{Y}年记.md` | `2026/2026年记.md` |

API 用 `granularity=day|week|month|quarter|year` + `date=YYYY-MM-DD`（或 ISO week 字符串）定位文件。

### 4.2 Frontmatter

- **默认不使用**；与现有日记样本一致。
- 若文件已含 `---` 块，**整文件仍按 Markdown 保存**；解析 Memos 时只扫描 `Memos` 段，不拆 frontmatter（P0 可要求 Memos 在 frontmatter 之后）。

### 4.3 模板与新建

- 日記：`Template/日记模板.md`。
- 占位符（P0 支持子集）：
  - `{{date:YYYY-MM-DD}}`、`{{date:YYYY-MM}}`、`{{date:YYYY}}`、`{{date:gggg-[W]ww}}` → 按目标日期格式化。
  - 未识别 `{{date:...}}` 或 Templater `<% %>`：**保留原样**并在 UI 提示「需在 Obsidian 中由 Templater 处理」。
- 新建当天日记：若文件不存在，`POST /api/diary/entries` 读模板、替换占位符、写入目标路径；**不**自动运行 Obsidian 插件。

### 4.4 `Memos` 段格式（精确）

1. 定位：文件中**最后一次**出现的独立行 `Memos`（trim 后完全匹配，大小写敏感，与 Thino 一致）。
2. 若不存在：新建时在模板末尾已有 `Memos\n`；对旧文件追加 `\n\nMemos\n`（需用户确认是否自动插入，见 §12）。
3. 条目边界：以行首 `- ` 开头且匹配 `- (\d{2}:\d{2})\s+(.*)$` 为新 memo；下一行若以 Tab 开头则为上一条的续行。
4. 追加：在 Memos 段**末尾**插入 `\n- {HH:mm} {content}`（24h，与 Thino `DefaultTimePrefix` 一致）；content 可含 `#标签`。
5. 编辑/删除：按「条目起始行 + 续行」整体替换或删除，写回文件；**禁止**只改 SQLite 而不同步文件。

## 5. 数据与索引策略

- **文件优先**：一切展示与导出以磁盘 `.md` 为准。
- **可选 SQLite 缓存**（`data/diary_index.db` 或复用 `app.db` 新表）：仅存 `relative_path`、`granularity`、`date_key`、`mtime`、`sha256`、`size`、memo 标签倒排索引；**可整表删除重建**。
- 重建：扫描 `DIARY_VAULT_ROOT` 下 `1.Diary`，解析每文件日期键与 Memos 标签；耗时 <1s 级（当前规模）。
- 失效：保存后更新该文件索引；`pull` 后对比 mtime/size/sha256，不一致则废缓存行。
- **禁止**：在 DB 存正文而与文件分叉；冲突未解决时不更新索引为「新正文」。

## 6. API 设计（REST）

风格对齐 `/api/stories`：`ok` 字段、中文 `error`、400/404/409/500。

### 6.1 日记条目

| 方法 | 路径 | 说明 |
|------|------|------|
| GET | `/api/diary/entries?from=&to=&granularity=day` | 日期范围内存在的条目列表（元数据） |
| GET | `/api/diary/entries/{date}?granularity=day` | 读单文件：`content`、`path`、`sha256`、`mtime` |
| PUT | `/api/diary/entries/{date}` | 整文件保存；body: `{ "content": "...", "base_sha256": "..." }` |
| POST | `/api/diary/entries` | 新建：`{ "date": "2026-10-25", "granularity": "day" }` 从模板创建 |

### 6.2 Memos（Thino）

| 方法 | 路径 | 说明 |
|------|------|------|
| GET | `/api/diary/memos?date=YYYY-MM-DD` | 解析当日 Memos 为 `[{ "time", "text", "line_start", "line_end" }]` |
| POST | `/api/diary/memos` | `{ "date", "text", "time"? }` 追加一条 |
| PATCH | `/api/diary/memos/{date}/{index}` | 按序号或 `line_start` 编辑 |
| DELETE | `/api/diary/memos/{date}/{index}` | 删除一条（含续行） |
| GET | `/api/diary/memos/search?q=&tag=` | P1：跨日扫描索引或文件 |

### 6.3 同步

| 方法 | 路径 | 说明 |
|------|------|------|
| POST | `/api/diary/sync/pull` | rclone sync S3→本地（可限 `1.Diary`+`Template`） |
| POST | `/api/diary/sync/push` | rclone sync 本地→S3（仅变更文件或子路径） |
| GET | `/api/diary/sync/status` | `{ "last_pull", "last_push", "dirty_files": [], "remote_ok" }` |

### 6.4 请求/响应示例

**读取：**

```http
GET /api/diary/entries/2026-10-21?granularity=day
```

```json
{
  "ok": true,
  "entry": {
    "date": "2026-10-21",
    "granularity": "day",
    "relative_path": "2026/日记/2026-10-21.md",
    "content": "…",
    "sha256": "a1b2…",
    "mtime": 1729512345.0,
    "exists": true
  }
}
```

**保存冲突：**

```http
PUT /api/diary/entries/2026-10-21
{ "content": "…", "base_sha256": "old_hash" }
```

```json
{
  "ok": false,
  "error": "远端已变更，请先同步",
  "code": "CONFLICT",
  "current_sha256": "new_hash",
  "remote_preview": "前 500 字…"
}
```

HTTP **409**，`code`: `CONFLICT` | `NOT_FOUND` | `VALIDATION` | `SYNC_FAILED`。

### 6.5 路由实现要点

- 在 `server.py` 增加 `_match_diary` 与 `_diary_api`，模块 `app/diary.py`（纯文件 IO + 可选索引），配置项写入现有 `config` JSON（与 `/api/config` 一致模式）。
- `diary.py` 职责拆分建议：`resolve_path(granularity, date)`、`read_entry`/`write_entry`、`parse_memos`/`append_memo`/`patch_memo`、`template_apply`、`file_sha256`；同步子进程调用封装在 `diary_sync.py` 或同模块 `run_rclone(args)`，超时与 stderr 映射为 `SYNC_FAILED`。
- 列表接口 `GET /api/diary/entries` 返回项字段：`date`、`granularity`、`relative_path`、`exists`、`title_guess`（首行或 `##` 后首段，可选）、`memo_count`（解析 Memos 条目数），不返回全文以减负。

### 6.6 错误码与 HTTP 状态

| HTTP | code | 典型 error 文案 |
|------|------|-----------------|
| 400 | VALIDATION | 日期格式无效 / Memos 解析失败 |
| 404 | NOT_FOUND | 文件不存在且未允许新建 |
| 409 | CONFLICT | 远端已变更，请先同步 |
| 500 | SYNC_FAILED | rclone 退出非 0 |
| 503 | VAULT_UNAVAILABLE | 镜像目录未挂载或不可读 |

### 6.7 配置项（`config.json` 或环境变量，示例无密钥）

```json
{
  "diary": {
    "vault_root": "/home/user/文档/笔记-mirror",
    "diary_subdir": "1.Diary",
    "template_subdir": "Template",
    "daily_template": "日记模板.md",
    "timezone": "Asia/Shanghai",
    "rclone_remote": "obsidian-vault",
    "rclone_subpath": "笔记",
    "auto_push_on_save": false,
    "write_token": ""
  }
}
```

`vault_root` 下应能拼出 `1.Diary/2026/日记/…` 与 `Template/日记模板.md`；与 rclone `sync` 的本地目标一致。

## 8. 同步与冲突（含双写）

### 8.1 协作协议（人与端）

1. **门户写入前**：用户或自动 `POST /api/diary/sync/pull`（打开页签、切换日期、点「同步」）。
2. **Obsidian 写入前**：用户在 PC/手机 **手动** remotely-save 同步（现有习惯）。
3. **门户写入后**：`PUT` 成功 → `POST push`，将镜像目录变更推到 S3。
4. **Obsidian 再次使用前**：手动 pull S3，避免基于旧缓存编辑。

### 8.2 双写冲突：网页 vs Thino（同一 `Memos` 段）

| 步骤 | 行为 |
|------|------|
| 检测 | 保存前 pull；比较服务端 `sha256` 与客户端 `base_sha256`；不等则 **409** |
| 门户 memo 追加 | 只改 Memos 段时也走「读全文件 → 改段 → 写全文件」，同样带 `base_sha256` |
| Thino 在 Obsidian 改 | 下次门户 pull 后 hash 变；若门户仍持旧 hash 保存 → 冲突弹窗 |
| 冲突 UI | 三选一：**放弃**（重载远端）、**覆盖**（需二次确认，写 `force: true` 仅限 P1 且记日志）、**复制本地草稿**到新剪贴板/下载 `.md` |
| 禁止 | 静默 last-write-wins |

### 8.3 S3 / ETag

- rclone 支持 S3 版本与 `Size`/`ModTime`；门户层以**文件 sha256** 为主键，pull 后更新。
- 若 S3 开启版本控制，P2 可从 rclone 日志或 `rclone lsjson` 拉历史版本；P0 仅检测「当前对象」变化。

## 13. 审核补充（DSH 审核，v1.1）

> 本节是对 Cursor 版设计文档的审核结论。**如与正文冲突，以本节为准。**

### 13.1 结论

方案 A（rclone 本地镜像 + S3）在当前约束下可行，是合理选择。但 P0 需要收窄，并先落实三条硬规则：**同步不删除、冲突查远端、保存保字节**。

### 13.2 必须修正的 6 点

**1）同步安全（最重要）**

- P0 **禁止** `rclone sync 本地→S3`：sync 会删除远端「本地没有」的文件。push 只允许 `rclone copy --update` 或 `rclone copyto` 单文件。
- pull 用 `rclone copy`（非破坏），不要用 sync 覆盖本地未保存内容；只有确认本地无未保存修改时才可 sync。
- 首次上线先 `rclone lsjson` / `ls` 对照 3 个真实文件（含中文 `日记`、空格、可能的 URL 编码），确认 bucket/prefix 与 remotely-save **完全一致**；不要凭配置猜。
- 所有 rclone 命令先 `--dry-run`，把输出给用户确认后再执行。

**2）冲突检测必须查远端**

- 只比较本地镜像 hash 检测不到「远端已变、本地还没 pull」的情况。
- `PUT /api/diary/entries` 必须先取远端当前文件（`rclone cat` 或 `copyto` 到临时文件）算 sha256，与 `base_sha256` 比对；不一致立即 409，不写本地、不 push。
- 文件只有几 KB，`rclone cat` 成本可接受；S3 ETag 在分片/加密场景不可靠，以**内容 sha256** 为准。

**3）单文件粒度同步**

- 打开/保存只同步当前文件（`rclone copyto`），不要每次整棵子树 sync；全量同步只放在「同步」按钮或定时任务。
- 这样把延迟和冲突窗口都压到最小。

**4）字节保真**

- 保存必须保留原文件的换行（LF）、Tab 缩进、未修改区域的原始字节；不要 trim / 重排 / 格式化。
- 追加/编辑 memo 只替换目标 memo 的起始行 + 续行，其他行原样保留。
- 写回用 UTF-8 无 BOM；原文件是 CRLF 则保持 CRLF（或 P0 只支持 LF 并在界面提示）。

**5）Memos 段与插入位置**

- 已核对 Thino 配置：`InsertType: end`、`InsertAfter` / `ProcessEntriesBelow` 为空、`saveThinoType: FILE`，因此「追加到 `Memos` 段末尾」与插件行为一致；`DefaultEditorLocation: Top` 只是编辑器位置，不改变插入位置。
- 段识别只认「最后一次独立行 `Memos`，且其后到 EOF 全是 memo / 空行」；正文出现 “Memos” 不得误判。
- 旧文件没有 `Memos` 段：P0 **不自动插入**，返回提示/按钮让用户决定，避免破坏版式。
- 旧文件 `Memos` 段后面还有别的标题：P0 拒绝自动追加并提示，避免插错段。

**6）P0 收窄**

- 建议 P0 = **只读日记（今日/指定日期）+ 快速 memo 追加 + 单文件 pull/push + 409 冲突提示**。
- **完整 Markdown 全文编辑放 P1**（字节保真、模板、冲突风险最高）。若 P0 就要编辑，至少先只读预览 + memo 追加，编辑功能单独开关。
- 周/月/季/年导航放 P1。

### 13.3 历史路径（实测，补正文 §4.1）

- 2026+：日 `1.Diary/2026/日记/YYYY-MM-DD.md`；周 `2026/周记/2026-W43.md`；月 `2026/月记/2026-10.md`；季 `2026/季度/2026-Q3.md`；年 `2026/2026年记.md`。
- 2025：`1.Diary/2025/YYYY-MM-DD.md`（扁平，无 `日记` 子目录）。
- 2023：`1.Diary/2023/YYYY-MM.md`（月记）与 `1.Diary/2023/YYYY-MM-DD 周X.md`（日，文件名含中文星期）。
- P0 日历只保证 2026+；历史年份作为 P2 兼容层，先不要承诺。
