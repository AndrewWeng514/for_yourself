# 日记功能 · 初步计划书（v0.1）

> 目标：在个人门户（`E:\codex项目`，Ubuntu 部署）新增「日记」能力，直接读写 `E:\文档\笔记` 的 Markdown 结构；同时保留 Thino 式网页记录。本文是初步骨架，交 Cursor 扩充为完整设计文档。

## 1. 目标与边界

- **Markdown 是唯一内容源**：日记、周记、月记、季记、年记都保留在 `E:\文档\笔记` 原有目录与文件里，不搬进 SQLite。
- **网页新增「日记」页签**：按日期打开/创建当天日记，Markdown 编辑 + 预览、保存；可按周/月/季/年导航（P1）。
- **网页保留 Thino 功能**：当日日记 `Memos` 段的快速记录、时间线、`#标签`、搜索、编辑/删除，格式与 Thino 兼容（`- HH:mm 内容`）。
- **不替换 Obsidian**：网页是补充入口，手机/桌面仍可用 Obsidian + Thino。

## 2. 现状与硬约束

- 门户：Python 标准库 + 原生 JS，零依赖；代码在 `E:\codex项目`，运行在 Ubuntu（`~/文档/dividend-app`，systemd + Tailscale）。
- 笔记库：`E:\文档\笔记`，结构为
  - `1.Diary/YYYY/日记/YYYY-MM-DD.md`（日）
  - `1.Diary/YYYY/周记/gggg-[W]ww.md`、`月记`、`季度`、年记
  - `Template/日记模板.md`、`周记模板.md` 等
  - 日记里有 `## 杂记`、`Memos` 段；Thino 配置 `MemoSaveLocation: DAILY`，memo 格式 `- HH:mm 内容`，续行 tab 缩进。
- 同步：Windows/手机端用 **remotely-save（S3）**，手动点击触发；Ubuntu 上没有笔记库、没有 rclone。
- 因此网页要读写 md，必须先解决「Ubuntu 如何拿到/回写笔记库」。

## 3. 推荐架构（待 Cursor 细化）

**rclone + S3 桥接，文件优先：**

```
Obsidian(Windows/iPhone) ⇄ remotely-save(S3) ⇄ rclone ⇄ Ubuntu 本地镜像 ~/文档/笔记
                                                              ↑
                                                        门户「日记」页签读写 md
```

- Ubuntu 只镜像 `1.Diary/` + `Template/`（约 0.1MB），不搬 Annex/Excalidraw。
- 网页直接读写本地 md；保存后 rclone 推 S3；设备端 remotely-save 拉取。
- 打开页签/编辑前先拉取；保存后推送；用 ETag/内容哈希做冲突检测。
- **不建日记数据库**；搜索按需扫描（数据很小）。如加索引必须可重建，且不能成为第二内容源。

## 4. MVP 范围

- 日记：今天、选择日期、模板创建、Markdown 编辑 + 预览、保存。
- Thino：当日 `Memos` 快速记录、时间线、标签、编辑/删除。
- 同步：打开拉取、保存推送、冲突提示（至少提示「远端已变化，先同步」）。

## 5. 关键风险

1. **双写冲突**：网页、Thino、remotely-save（手动）三方写同一篇 md；需要「拉取→编辑→推送」+ 冲突检测，不能静默覆盖。
2. **模板语法**：`Template/日记模板.md` 用 `{{date:...}}`；网页只替换简单日期占位符，Templater 复杂语法保持只读并提示。
3. **同步依赖**：rclone、S3 凭据、Ubuntu 镜像目录权限；S3 后端与 remotely-save 必须一致。
4. **「保留 md」的边界**：是否允许 SQLite 缓存/索引、是否允许网页新建/删除文件，需要在设计文档里写死。

## 6. 分阶段

- **P0**：rclone 镜像 + 日记读写（当天/按日期）+ 模板创建 + Thino 快速记录 + 打开拉取/保存推送。
- **P1**：周/月/季/年导航、Memos 编辑删除、标签/搜索、冲突提示 UI。
- **P2**：反向链接、附件、版本历史、多端冲突合并。
