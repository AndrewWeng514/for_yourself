# 运维与备份

## 代码部署

`deploy.sh` 现在会：

1. 同步 `app/ web/ server.py`；
2. 在服务器 `.deploy-backups/` 备份旧代码；
3. 重启 `dividend-app.service`；
4. 健康检查失败时自动恢复旧代码并重启；
5. 只保留最近 10 份代码备份。

部署不包含 `data/`、`logs/`，不会覆盖日记和数据库。

## 数据备份

在 Ubuntu 上运行：

```bash
bash ~/文档/dividend-app/scripts/backup_portal.sh
```

默认备份：

- `~/文档/portal-diary/`
- `~/文档/dividend-app/data/app.db`
- 输出到 `~/portal-backups/portal-YYYYmmdd-HHMMSS.tgz`
- 保留 14 天

可用环境变量覆盖：

```bash
PORTAL_DIARY_DIR=...
PORTAL_DB=...
PORTAL_BACKUP_DIR=...
PORTAL_BACKUP_KEEP_DAYS=30
```

### 建议的 systemd timer

创建 `~/.config/systemd/user/portal-backup.service`：

```ini
[Unit]
Description=Backup personal portal

[Service]
Type=oneshot
ExecStart=/usr/bin/bash %h/文档/dividend-app/scripts/backup_portal.sh
```

创建 `~/.config/systemd/user/portal-backup.timer`：

```ini
[Unit]
Description=Daily personal portal backup

[Timer]
OnCalendar=*-*-* 03:30:00
Persistent=true

[Install]
WantedBy=timers.target
```

启用：

```bash
systemctl --user daemon-reload
systemctl --user enable --now portal-backup.timer
```

## 恢复演练

```bash
mkdir -p /tmp/portal-restore
tar -tzf ~/portal-backups/portal-YYYYmmdd-HHMMSS.tgz | head
tar -xzf ~/portal-backups/portal-YYYYmmdd-HHMMSS.tgz -C /tmp/portal-restore
```

确认文件完整后，再按需要恢复；恢复前先停服务并另存当前数据。

## 访问边界

门户包含财务与日记数据。默认监听 `0.0.0.0:8000`，局域网可访问；如果通过 frp / Tailscale Funnel 暴露到公网，必须先在反向代理层加认证（Basic Auth / OAuth），不要直接暴露 8000。

### 可选 Basic Auth

设置环境变量后启用：

```bash
PORTAL_AUTH_USER=portal
PORTAL_AUTH_PASSWORD=换成强密码
```

`/api/health` 不需要认证，方便部署健康检查；其他页面和 API 都会要求 Basic Auth。未设置 `PORTAL_AUTH_PASSWORD` 时保持原行为。
